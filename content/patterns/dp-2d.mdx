## Intuition

Some problems can't be described by one index. Comparing two strings needs a position in **each**. A grid path needs a **row and a column**. A knapsack needs the **item** and the **remaining capacity**. The DP recipe from 1-D DP doesn't change — state, transition, base cases, order — the state just has two coordinates, so the cache becomes a table.

Picture filling a spreadsheet: each cell is computed from cells above it and to its left. Fill row by row, and every cell you need is ready.

Common table shapes:

- **Grid paths**: `dp[r][c]` comes from `dp[r-1][c]` and `dp[r][c-1]` (Unique Paths, Minimum Path Sum).
- **Two sequences**: `dp[i][j]` is the answer for prefixes `a[:i]` and `b[:j]`. If the last characters match, step diagonally; otherwise take the best of dropping one character (LCS, Edit Distance, Regex Matching).
- **Item × capacity (knapsack)**: `dp[i][a]` uses the first i items to reach amount a (Coin Change II, Target Sum). It often shrinks to a single row.
- **Index × state**: a small state machine per day, like "holding a stock / sold / cooling down".

## Template

```python
def unique_paths(m: int, n: int) -> int:
    """Grid DP squeezed into one row: row[c] = paths from above + paths from the left."""
    row = [1] * n
    for _ in range(1, m):
        for c in range(1, n):
            row[c] += row[c - 1]
    return row[-1]


def lcs(a: str, b: str) -> int:
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]   # extra row/col = empty prefix
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]


def edit_distance(a: str, b: str) -> int:
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        dp[i][0] = i                               # delete everything
    for j in range(n + 1):
        dp[0][j] = j                               # insert everything
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i - 1][j],      # delete
                                   dp[i][j - 1],      # insert
                                   dp[i - 1][j - 1])  # replace
    return dp[m][n]


def coin_change_ways(coins: list[int], amount: int) -> int:
    """Coin Change II: number of combinations (order doesn't matter)."""
    dp = [1] + [0] * amount
    for c in coins:                                # coins in the OUTER loop
        for a in range(c, amount + 1):
            dp[a] += dp[a - c]
    return dp[amount]
```

## Complexity

- Time: **O(m · n)** — one constant-time transition per cell.
- Space: **O(m · n)** for the full table, usually reducible to **O(n)** by keeping only the previous row (or one row updated in place).
- Knapsack-style problems: **O(items × capacity)**.

## Pitfalls

- Off-by-one with the padded table: `dp[i][j]` refers to `a[i - 1]` and `b[j - 1]`.
- Forgetting base cases for the empty prefixes — Edit Distance needs row 0 and column 0 filled with 0..m and 0..n.
- Coin Change II loop order: coins outer, amounts inner counts **combinations**; swapping them counts **permutations** (2+1 and 1+2 separately).
- Shrinking to one row and then reading a value you've already overwritten. Go right-to-left (0/1 knapsack) or keep a `prev` variable for the diagonal.
- Target Sum with negative intermediate sums: shift by the total, or turn it into a subset-sum problem with `(total + target) / 2`.

## Tips & tricks

- Write the brute-force recursion with two arguments, memoise it with `@cache`, and only then convert it to a table if needed.
- Minimum Path Sum: the same as Unique Paths with `min` and the cell's cost instead of `+`.
- Stock with Cooldown: three states per day — `hold`, `sold`, `rest` — with transitions between them; only yesterday's values are needed.
- Regular Expression Matching: `*` either matches zero of the previous token (`dp[i][j-2]`) or one more character if it matches (`dp[i-1][j]`).
- If one of the two indices only ever looks at its previous value, you can drop that dimension — sometimes a 2-D problem is secretly **1-D DP**.
