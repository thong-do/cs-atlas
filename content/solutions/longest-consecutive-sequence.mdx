## Intuition

Picture each number as one step, so that consecutive numbers form a staircase: 2, 3, 4 is a staircase of three steps. To measure a staircase you stand on its bottom step and count upward until the next step is missing. The bottom step is easy to recognise, because there is no step one below it. If you only ever start from bottom steps, each staircase is climbed exactly once, and the tallest climb is the answer.

## Brute force

From every number, count upward for as long as the next number is somewhere in the list.

1. For each number `x`, set `length` to 1.
2. While `x + length` is in `nums`, add one to `length`.
3. Keep the largest `length` in `longest`.

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        longest = 0
        for x in nums:
            length = 1
            while x + length in nums:     # scans the whole list each time
                length += 1
            longest = max(longest, length)
        return longest
```

Trace for `nums = [3, 9, 2, 4, 3]`:

| x | x + length in nums? | length | longest |
|---|---|---|---|
| 3 | 4 yes, 5 no | 2 | 2 |
| 9 | 10 no | 1 | 2 |
| 2 | 3 yes, 4 yes, 5 no | 3 | 3 |
| 4 | 5 no | 1 | 3 |
| 3 | 4 yes, 5 no | 2 | 3 |

**Complexity:** O(n³) time in the worst case: each `in` check scans up to n numbers, and when the numbers are one long run, the climbs from all starts add up to about n²/2 checks. O(1) extra space.

**What's wasted:** each `in` check searches the whole list, and the same staircase is climbed again from every one of its steps (the climb 3, 4 is done twice above). Sorting lines each staircase up in a row, so one walk measures every staircase once.

## Better

Sort the numbers so each run sits side by side, then walk once, extending or restarting the current run.

1. If `nums` is empty, return 0; otherwise sort it into `sorted_nums`.
2. Walk `sorted_nums`, skipping a number equal to the one before it.
3. If it is one more than the one before, add one to `length`; otherwise restart `length` at 1.
4. Keep the largest `length` in `longest`.

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        if not nums:
            return 0
        sorted_nums = sorted(nums)
        longest = length = 1
        for i in range(1, len(sorted_nums)):
            if sorted_nums[i] == sorted_nums[i - 1]:
                continue                  # a repeat neither extends nor breaks the run
            if sorted_nums[i] == sorted_nums[i - 1] + 1:
                length += 1
            else:
                length = 1
            longest = max(longest, length)
        return longest
```

Trace for `nums = [3, 9, 2, 4, 3]`, so `sorted_nums = [2, 3, 3, 4, 9]`:

| i | sorted_nums[i] | length | longest |
|---|---|---|---|
| (start) | 2 | 1 | 1 |
| 1 | 3 | 2 | 2 |
| 2 | 3 (repeat, skipped) | 2 | 2 |
| 3 | 4 | 3 | 3 |
| 4 | 9 | 1 | 3 |

**Complexity:** O(n log n) time for the sort, then O(n) for the walk. O(n) extra space for the sorted copy.

**What's wasted:** the sort puts every number in order, but the walk only ever asks "is the number one above present?". A set answers that in O(1) on average without ordering anything, as long as each staircase is still climbed only from its bottom step.

## Optimal

Put the numbers in a set, and climb only from numbers with no predecessor, the bottom steps of their staircases.

1. Put every number into a set, `num_set`.
2. For each `x` in `num_set`, skip it if `x - 1` is in `num_set`: it is not a bottom step.
3. From a bottom step, count `length` upward while `x + length` is in `num_set`.
4. Keep the largest `length` in `longest`.

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        num_set = set(nums)
        longest = 0
        for x in num_set:
            if x - 1 not in num_set:      # x is the bottom step of a staircase
                length = 1
                while x + length in num_set:
                    length += 1
                longest = max(longest, length)
        return longest
```

Trace for `nums = [3, 9, 2, 4, 3]`. A set promises no order, and here Python visits `num_set` as 9, 2, 3, 4:

| x | x - 1 in num_set? | length | longest |
|---|---|---|---|
| 9 | no, so climb 9 | 1 | 1 |
| 2 | no, so climb 2, 3, 4 | 3 | 3 |
| 3 | yes, skip | | 3 |
| 4 | yes, skip | | 3 |

The duplicate 3 is gone in the set, and 3 and 4 are skipped because the climb from 2 covers them. The order of the loop doesn't matter: each staircase is climbed once, from its bottom step, whenever that step comes up.

**Complexity:** O(n) time on average: building the set is O(n), and each number is stepped onto at most once by a climb and checked once as a possible start, all with average-O(1) set lookups. Looping over `num_set` rather than `nums` matters: with many copies of a bottom step, looping over `nums` would repeat the same climb. O(n) extra space for `num_set`.
