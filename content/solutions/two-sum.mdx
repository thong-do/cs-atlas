## Intuition

People walk past you one at a time, each holding a number, and you want two whose numbers add up to the target. Instead of making each newcomer compare themselves with everyone who came before, you keep a notebook of every number you have seen and where. Each newcomer works out the partner they need, target minus their own number, and you check the notebook for it. If it isn't there, you write the newcomer down, so that their partner, when they turn up later, will find them.

## Brute force

Try every pair of positions and return the first pair that adds up to `target`.

1. Pick each position `i` in turn.
2. Pair it with every later position `j`.
3. Return `[i, j]` as soon as `nums[i] + nums[j]` equals `target`.

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] + nums[j] == target:
                    return [i, j]
        return []
```

Trace for `nums = [4, 1, 5, 3]`, `target = 8`:

| i | j | nums[i] + nums[j] | equals 8? |
|---|---|---|---|
| 0 | 1 | 5 | no |
| 0 | 2 | 9 | no |
| 0 | 3 | 7 | no |
| 1 | 2 | 6 | no |
| 1 | 3 | 4 | no |
| 2 | 3 | 8 | yes, return `[2, 3]` |

**Complexity:** O(n²) time, because in the worst case all n(n − 1)/2 pairs are tried. O(1) extra space.

**What's wasted:** for each `i`, the inner loop scans the later numbers looking for one specific value, `target - nums[i]`. Looking a value up by what it is, instead of scanning for it, is exactly what a hash map does, in O(1) on average.

## Optimal

Walk the list once; for each number, look up the partner it needs among the numbers already passed, then record the number itself.

1. Start with an empty map, `seen`, from value to index.
2. For each index `i` and value `x`, work out `need`, the target minus `x`.
3. If `need` is in `seen`, return its index together with `i`.
4. Otherwise record `x` with its index `i` in `seen`, and move on.

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}                     # value -> index
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:
                return [seen[need], i]
            seen[x] = i               # record x only after checking, so x never pairs with itself
        return []
```

Trace for `nums = [4, 1, 5, 3]`, `target = 8`:

| i | x | need | need in seen? | seen afterwards |
|---|---|---|---|---|
| 0 | 4 | 4 | no | `{4: 0}` |
| 1 | 1 | 7 | no | `{4: 0, 1: 1}` |
| 2 | 5 | 3 | no | `{4: 0, 1: 1, 5: 2}` |
| 3 | 3 | 5 | yes, at 2 | return `[2, 3]` |

At `i = 0` the 4 needs another 4. It isn't in `seen` yet, because the check runs before the 4 is written down, so the 4 is not paired with itself.

**Complexity:** O(n) time on average: one map lookup and one insert per number, each O(1) on average. O(n) extra space for `seen` in the worst case.
