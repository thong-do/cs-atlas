## Intuition

A greedy algorithm makes the choice that looks best **right now** and never revisits it. When that's safe, you get a fast, simple one-pass solution. When it isn't, greedy quietly returns a wrong answer — so the real skill is knowing **why** the local choice can't hurt you.

Think of giving change with coins of 25, 10, 5 and 1 cents: always hand over the biggest coin that fits. With these coins that's always optimal. With coins of 1, 3 and 4 it fails for 6 (4+1+1 instead of 3+3). Same idea, different safety — that's the whole game.

How to convince yourself a greedy choice is safe:

- **Exchange argument**: take any optimal solution that doesn't make your choice, swap your choice in, and show it's still at least as good.
- **"Nothing better is possible"**: in Jump Game, if you can't reach index i, you can't reach anything past it either.
- **Try to break it**: spend two minutes hunting for a counter-example. If you find one, you probably need **DP**.

Common shapes:

- **Best-so-far in one pass**: Kadane's maximum subarray (drop a prefix once it goes negative), Jump Game (track the farthest reachable index).
- **Running balance that resets**: Gas Station — when the tank goes negative, no start up to here can work, so restart after it.
- **Sort, then take**: Hand of Straights (always start groups from the smallest card), plus the "sort by end" interval trick.

**What greedy needs to be correct.** Two things must hold. After you make the choice, what's left must be a smaller problem of the same kind. And the choice must be **safe**: some best answer includes it. The second is the hard part, and the exchange argument is how you prove it. Here's that argument on a real rule, from the Example below: to minimise the worst delay, do the job due soonest first.

Take any schedule that isn't in due-date order. Somewhere in it, a job `a` runs directly before a job `b`, though `b` is due sooner. Swap the two. Both together still end at the same time T, and every other job is untouched. Job `b` now finishes earlier, which can't hurt. Job `a` now finishes at T, so it's late by T − due(a). That's less than b's old lateness, T − due(b), because `a` is due later. So the worst delay doesn't go up. Repeat until no such pair is left, and you've turned any schedule, including the best one, into due-date order at no cost.

**A case where greedy fails.** You can carry 7 kg, and each item is taken whole: 5 kg worth 10, 4 kg worth 7, and 3 kg worth 5. Taking the best value per kilo first picks the 5 kg item (2 per kilo). Nothing else fits, so the total is 10. The best answer takes the other two for 12. See where the exchange breaks: to swap the 5 kg item in, you may have to remove two items, so one swap doesn't compare like with like. If you could cut items, the same rule would be correct, since you can trade any weight for an equal weight of something better.

A failed proof isn't a counterexample, though, so you still need to test the rule. And a few passed tests aren't a proof either. The small brute force is worth writing: try all choices on tiny inputs and compare.

**When not to use it.** If you've found an input that beats the rule, stop patching the rule. If an early choice decides which choices you have later, and you can't show that it's harmless, consider every option with [1-D DP](/algorithms/dp-1d/). And if the task is to list every solution, greedy can't help, because it produces only one: use [Backtracking](/algorithms/backtracking/).

**Telling it from its neighbours.** **DP** keeps the best answer for every state and compares options, while greedy commits to one option and never compares again. DP is the safer of the two and usually slower. [Intervals](/algorithms/intervals/) is a family of problems, and greedy is one technique used on it: "keep the range that ends first" is greedy, while merging ranges makes no choice at all.

## Template

```python
def max_subarray(nums: list[int]) -> int:
    """Kadane: extend the current run, or start fresh at x if the run only hurts."""
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best


def can_jump(nums: list[int]) -> bool:
    reach = 0
    for i, step in enumerate(nums):
        if i > reach:                 # this index can't be reached
            return False
        reach = max(reach, i + step)
    return True


def min_jumps(nums: list[int]) -> int:
    """Jump Game II: BFS by 'windows' — each jump covers the next window."""
    jumps = window_end = farthest = 0
    for i in range(len(nums) - 1):
        farthest = max(farthest, i + nums[i])
        if i == window_end:           # used up this jump's range
            jumps += 1
            window_end = farthest
    return jumps


def gas_station(gas: list[int], cost: list[int]) -> int:
    if sum(gas) < sum(cost):
        return -1                     # not enough fuel overall
    tank = start = 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0:                  # no start in [start, i] can work
            start, tank = i + 1, 0
    return start
```

## Example

**The problem.** A print shop has one press and a list of orders, each with the hours it takes and the hour it's due. All orders are ready at hour 0, and the press runs without gaps, one order at a time. Choose the order of work that makes the **worst delay** as small as possible, and return that delay. An order finished on time counts as a delay of 0.

**Spotting the pattern.** The trigger is "a locally best choice is provably safe", in the "sort, then take" shape. The result of the exchange argument above is that one number, the due date, decides the whole order.

**Why brute force is slow.** You could try every order of work. 10 orders have 3,628,800 orderings, and 15 orders have about 1.3 trillion. That's O(n · n!).

**The key insight.** Do the order due soonest first. Notice what the rule ignores: the hours. Tempting rules such as "shortest job first" fail, as the run below shows.

```python
def worst_delay(orders: list[tuple[int, int]]) -> int:
    """Each order is (hours, due)."""
    clock = worst = 0
    for hours, due in sorted(orders, key=lambda order: order[1]):
        clock += hours
        worst = max(worst, clock - due)
    return worst
```

**Traced run** on `[(3, 7), (4, 4), (1, 8), (2, 5)]`, after sorting by due hour:

| Hours | Due | Clock when done | Late by | worst |
|---|---|---|---|---|
| 4 | 4 | 4 | 0 | 0 |
| 2 | 5 | 6 | 1 | 1 |
| 3 | 7 | 9 | 2 | 2 |
| 1 | 8 | 10 | 2 | 2 |

The answer is 2. Shortest job first on the same orders runs the 4-hour order last. It finishes at hour 10 against a due hour of 4, a delay of 6. Sorting is O(n log n), and the pass is O(n).

## Complexity

- Most greedy solutions are a single pass: **O(n)** time, **O(1)** space.
- Add **O(n log n)** when the greedy choice needs sorted input (Hand of Straights, interval problems).

## Pitfalls

- Using greedy without a reason it's safe. Coin Change with arbitrary coins and 0/1 knapsack look greedy but need **DP**. Longest Increasing Subsequence also defeats "take the next larger element"; its O(n log n) method pairs a greedy update with binary search ([1-D DP](/algorithms/dp-1d/)).
- Kadane with `best = 0` as the start — an all-negative array then returns 0 instead of its largest element.
- Jump Game II: looping to the last index and counting one jump too many — stop at `len(nums) - 1`.
- Gas Station: forgetting the total-fuel check, which is what makes "restart after the failure point" correct.
- Valid Parenthesis String: trying all three meanings of `*` by recursion — instead track the **range** of possible open counts `[low, high]`.

## Tips & tricks

- Ask: "what is the best decision for the next step, and what would I lose by making it?" If the answer is "nothing", it's greedy.
- Partition Labels: record each letter's last index, then extend the current part's end to the max last index seen and cut when `i` reaches it.
- Hand of Straights: count cards in a `Counter`, then repeatedly start a group at the smallest remaining card.
- Lemonade Change: always give back a $10 before two $5s when making $15 change — $5 bills are more flexible.
- When greedy fails a counter-example, the same problem usually has a **1-D DP** solution that considers every choice.
