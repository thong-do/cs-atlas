## Intuition

A hash set answers "is this exact word here?" in O(1). It can't answer "which words **start with** `car`?" without checking every word. A **trie** (prefix tree) can: each edge is one character, so every path from the root spells a prefix, and words that share a prefix share the same path.

Think of a phone's contact search. As you type `T`, `To`, `Tom`, the list narrows. A trie stores that narrowing directly: walking one letter deeper discards everything that doesn't match.

Two ideas cover the ladder:

- **Walk the word**: insert, search and prefix-check all follow the characters one node at a time. Mark the node where a word *ends* (`is_word`), because `car` and `cart` share nodes.
- **Walk the trie alongside something else**: a wildcard `.` tries every child; Word Search II walks the grid *and* the trie together, stopping as soon as a path isn't a prefix of any word.

**When not to use it.** If you only ever ask "is this exact word here?", a hash set is simpler. A trie also costs memory: every node holds its own dictionary, so it pays off only when prefix questions are the point. If the word list never changes and you only need to find the words under a prefix, sorting it also works, because words sharing a prefix sit next to each other and binary search finds where they start.

**Telling it from its neighbours.** [Arrays & Hashing](/algorithms/arrays-hashing/) can fake prefix checks by storing every prefix in a set. That answers "does this prefix exist?", but a word of L letters then adds L keys holding about L²/2 characters, and the set still can't list the words under a prefix. A trie shares those prefixes as one path. [Backtracking](/algorithms/backtracking/) is a way of searching, and a trie is a way of storing. They meet in Word Search II: backtracking walks the grid, and the trie says when to give up on a path.

## Template

```python
class TrieNode:
    def __init__(self):
        self.children: dict[str, "TrieNode"] = {}
        self.is_word = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True

    def _walk(self, s: str) -> TrieNode | None:
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.is_word

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None


def search_with_dots(node: TrieNode, word: str, i: int = 0) -> bool:
    """'.' matches any single letter (Design Add and Search Words)."""
    if i == len(word):
        return node.is_word
    if word[i] == ".":
        return any(search_with_dots(child, word, i + 1) for child in node.children.values())
    child = node.children.get(word[i])
    return child is not None and search_with_dots(child, word, i + 1)
```

## Example

**The problem.** A phone carrier prices calls by dial prefix. A rate table maps prefixes to cents per minute, and a call is billed at the rate of the **longest** prefix that its number starts with. A number that matches no prefix isn't billed. Given the rate table and a list of `(number, minutes)` calls, return the total bill in cents.

**Spotting the pattern.** The trigger is "many prefix queries": every call asks which stored prefixes its number starts with.

**Why brute force is slow.** You could compare each number with every prefix and keep the longest match. With 50,000 prefixes and 10,000 calls, that's 500 million prefix comparisons, and the bill for one call means reading the whole table.

**The key insight.** Prefixes that a number starts with all lie on one path from the root, the path that spells the number. So walk the number down the trie and remember the last rate you passed. The walk stops as soon as a digit has no child, because no longer prefix can match. Compare Replace Words on the ladder, which wants the **first** marked node. Here you keep going, because a later mark beats an earlier one.

```python
class RateNode:
    def __init__(self):
        self.children: dict[str, "RateNode"] = {}
        self.rate: int | None = None


def total_bill(rates: dict[str, int], calls: list[tuple[str, int]]) -> int:
    root = RateNode()
    for prefix, rate in rates.items():
        node = root
        for digit in prefix:
            node = node.children.setdefault(digit, RateNode())
        node.rate = rate

    bill = 0
    for number, minutes in calls:
        node, best = root, None
        for digit in number:
            node = node.children.get(digit)
            if node is None:
                break
            if node.rate is not None:     # a rate of 0 still counts
                best = node.rate
        if best is not None:
            bill += best * minutes
    return bill
```

**Traced run** with rates `1` → 10, `12` → 7, `125` → 4, `44` → 9, and calls `1258` for 3 minutes, `1390` for 2, `4412` for 5 and `4712` for 1:

| Number | Digit | At this node | Best rate | Bill |
|---|---|---|---|---|
| 1258 | 1 | rate 10 | 10 | 0 |
| 1258 | 2 | rate 7 | 7 | 0 |
| 1258 | 5 | rate 4 | 4 | 0 |
| 1258 | 8 | no such child, stop | 4 | 0 |
| 1258 | end of walk | 3 min × 4 | 4 | 12 |
| 1390 | 1 | rate 10 | 10 | 12 |
| 1390 | 3 | no such child, stop | 10 | 12 |
| 1390 | end of walk | 2 min × 10 | 10 | 32 |
| 4412 | 4 | no rate here | none | 32 |
| 4412 | 4 | rate 9 | 9 | 32 |
| 4412 | 1 | no such child, stop | 9 | 32 |
| 4412 | end of walk | 5 min × 9 | 9 | 77 |
| 4712 | 4 | no rate here | none | 77 |
| 4712 | 7 | no such child, stop | none | 77 |
| 4712 | end of walk | no rate, not billed | none | 77 |

The bill is 77 cents. `4712` shows why the `4` node's missing rate matters: it's on the path of a real prefix, `44`, but the number leaves that path before reaching a rate.

**Would a hash map do?** For this problem, nearly. Put the prefixes in a dictionary and try each prefix of the number from longest to shortest. Hashing each one reads its characters, so that's O(L²) character work per number against the trie's O(L), and at 15 digits the difference is small. The trie earns its place as strings get longer, or when you also need what lies under a prefix, such as every rate starting `12`.

## Complexity

- Insert / search / prefix check: **O(L)** for a word of length L — independent of how many words are stored.
- Space: **O(total characters)** in the worst case, less when words share prefixes.
- Wildcard search: up to **O(26^d · L)** with d dots, since each `.` branches into every child.

## Pitfalls

- Forgetting `is_word`: without it, `search("ca")` wrongly returns True because the path exists.
- Treating "prefix exists" and "word exists" as the same check — they differ by that one flag.
- Word Search II: not marking grid cells as visited during the walk, so a cell is reused within one word.
- Word Search II: returning the same word twice — clear `is_word` (or the stored word) after you find it.
- Using a trie when a hash set is enough. If you never ask about prefixes, a set is simpler and just as fast.

## Tips & tricks

- `node.children.setdefault(ch, TrieNode())` creates-or-gets in one line.
- Store the full word at its end node (`node.word = word`) so a DFS can collect matches without rebuilding strings.
- Search Suggestions System: walk the trie one typed letter at a time, then DFS in alphabetical order from that node to collect up to 3 words.
- Replace Words: for each word, walk the trie and stop at the **first** node marked as a root word.
- Prune the trie as you go in Word Search II (delete leaf nodes once their word is found) to avoid re-exploring dead branches.
